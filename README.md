# winc1980/law

コンピュータ研究会・WINC の会則および諸規則を、一定のスキーマに従った JSON として管理するリポジトリです。
JSON が原本であり、公開ページはそこから生成されます。

公開先: https://winc1980.github.io/law/

## ディレクトリ構成

```
data/      会則・諸規則の JSON（原本）
schema/    JSON Schema。データ形式の唯一の定義
scripts/   検証・型生成・テスト
src/       公開ページと編集ページ（Astro）
  lib/     採番・和暦・保存形式・差分などのロジック
  types/   schema/ から自動生成される型定義。手で編集しない
```

## セットアップ

```sh
npm install
npm run dev      # http://localhost:4321/law/
```

## コマンド

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 開発サーバーを起動する |
| `npm run validate` | `data/` の JSON を `schema/` に照らして検証する |
| `npm test` | `src/lib` のロジック（保存形式・差分）を検査する |
| `npm run build` | 検証とテストを通してから静的サイトを `dist/` に出力する |
| `npm run check` | 検証・テスト・型チェックをまとめて実行する |
| `npm run gen:types` | `schema/` から `src/types/law.d.ts` を再生成する |

## 会則を直す

### 編集ページから（会員向け）

<https://winc1980.github.io/law/edit/constitution/> でフォームから編集できます。JSON を
書く必要はありません。フォームの項目は `schema/` から自動生成されるので、スキーマを直せば
入力欄も一緒に変わります。

編集内容はブラウザの中だけに留まります。「変更内容を確認」を押すと、どの条をどう変えたかの
一覧と、条番号の参照が壊れていないかの警告が出ます。そのうえで JSON をコピーし、GitHub の
編集画面に貼り付けてプルリクエストを作成します。書き込み権限がなければ自動でフォークされます。

現時点では**既存の規則の改正**のみに対応しています。新しい規則を起こす場合は JSON を直接
追加してください。

### JSON を直接編集する

`data/constitution.json` の先頭に `$schema` 参照があるため、VS Code（リポジトリ上で `.` キーを
押して開く github.dev を含む）では入力補完と検証が効きます。編集したら次を実行してください。

```sh
npm run validate
```

### いずれの場合も

会則の変更には理事会の決議が必要です（第26条）。JSON への反映はプルリクエストで行い、
決議を経てから main へ取り込んでください。

## データ形式

### 条番号は保存しない

条番号は配列順から自動採番されます。章をまたいで通し番号になり、附則は採番の対象外です。

そのため**条を挿入・削除すると、それ以降の条番号がすべてずれます**。会則の本文には
「第6条の義務に違反する行為」（第8条）のように条番号での参照が直接書かれているため、
条を増減させたときは参照の書き換えが必要です。

`npm run validate` は存在しない条への参照を検出しますが、参照先が意味的に正しいかまでは
見ていません。条の増減を伴う改正では、既存の参照を目視で確認してください。

### `id` は変更しない

条と章の `id` は、条番号がずれても壊れない固定の識別子です。公開ページの恒久リンク
（`#art-member-duties` など）に使われます。**一度付けた `id` は変更しないでください。**
見出しを直しても `id` はそのままにします。

編集ページでは `id` を表示していません。変更を誘って既存のリンクを壊すのを避けるためで、
新しい条には `a-3f9c2b1d` のような値が自動で振られます。意味のある英字スラッグに変えたい
場合は、プルリクエスト上で直してください（取り込まれる前なら安全に変えられます）。

### 附則

制定・改正のたびに `supplementaryProvisions` へ 1 件追加します。日付は ISO 形式で保存し、
表示時に和暦へ変換されます。

```json
{
  "kind": "一部改正",
  "effectiveDate": "2026-04-01",
  "resolvedOn": "2026-03-15",
  "resolvedBy": "理事会",
  "reason": "会費の改定"
}
```

`resolvedOn`・`resolvedBy`・`reason` は任意ですが、今後の改正では記録することを推奨します
（既存の 6 件は施行日しか記録が残っていないため未設定です）。

### スキーマを変えるとき

`schema/*.json` を直したら `npm run gen:types` で型定義を再生成し、両方をコミットしてください。
CI は生成物が最新でないと失敗します。

スキーマの `title` は編集フォームのラベルとして使われます（`description` は補足説明として
入力欄の下に出ます）。型生成では `title` を落としてから処理しているので、日本語を入れても
型名は壊れません。

## 今後の予定

このリポジトリは、一般会員が改正案を提出できるようにすることを目標に段階的に整備しています。

- **Phase 0（完了）** スキーマの確定と閲覧ページの公開
- **Phase 1（完了）** JSON Schema から生成した編集フォーム。変更内容を確認したうえで、
  プルリクエストとして提出できる
- **Phase 2** GitHub 認証の中継。いまは JSON をコピーして貼り付ける手順が要るが、これを
  自動化してボタン一つでプルリクエストを作れるようにする。あわせて条文レベルの新旧対照表を
  自動生成し、プルリクエスト本文に載せる
- **Phase 3** 効力（案 → 施行待ち → 施行中）の遷移チェック
