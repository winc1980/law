# winc1980/law

コンピュータ研究会・WINC の会則および諸規則を、一定のスキーマに従った JSON として管理するリポジトリです。
JSON が原本であり、公開ページはそこから生成されます。

公開先: https://winc1980.github.io/law/

## ディレクトリ構成

```
data/      会則・諸規則の JSON（原本）
schema/    JSON Schema。データ形式の唯一の定義
scripts/   検証・生成・テスト
src/       公開ページと編集ページ（Astro）
  components/ 条文の描画。公開ページと編集画面で共有する
  lib/     採番・和暦・保存形式・差分などのロジック
  types/   schema/ から自動生成される型定義。手で編集しない
  generated/ schema/ から自動生成される検証関数。手で編集しない
```

## セットアップ

```sh
npm install
npm run dev      # http://localhost:4321/law/
```

## コマンド

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 開発サーバーを起動する |
| `npm run validate` | `data/` の JSON を `schema/` に照らして検証する |
| `npm run validate:strict` | 上に加え、施行日のない附則をエラーにする（main 用） |
| `npm test` | `src/lib` のロジック（保存形式・差分・編集操作）を検査する |
| `npm run build` | 検証とテストを通してから静的サイトを `dist/` に出力する |
| `npm run check` | 検証・テスト・型チェックをまとめて実行する |
| `npm run gen` | `schema/` から型定義と検証関数を再生成する |

## 会則を直す

### 編集ページから（会員向け）

<https://winc1980.github.io/law/edit/constitution/> で編集できます。JSON を書く必要はありません。

画面は一画面で完結します。上部に法令名と効力、左に**公開ページと同じ見た目のまま書き換えられる本文**、
右に**変更した箇所の差分**が並びます。条を足すと条番号がその場で繰り下がり、影響を受ける参照が
右側に警告として出ます。

- 条番号・章番号・項番号・号番号は自動で振られます。編集するのは本文だけです。
- 条や章の追加・削除・並べ替えは、その条にカーソルを合わせると出るボタンで行います。
- 条の並べ替えは章をまたげます。章の切り分けはこれで行えます。
- 構造を変えたあとは <kbd>元に戻す</kbd> で戻せます。

提出すると**改正の理由**を尋ねられ、附則が1件足されます。議決日と施行日はこの時点では空のままで、
議決のあとに書き入れます。そのうえで JSON をコピーし、GitHub の編集画面に貼り付けて
プルリクエストを作成します。書き込み権限がなければ自動でフォークされます。

**種別と効力は編集できません。** 議決によって決まるものなので、変更が要る場合は JSON を
直接編集します。現時点では**既存の規則の改正**のみに対応しています。新しい規則を起こす場合も
JSON を直接追加してください。

### JSON を直接編集する

`data/constitution.json` の先頭に `$schema` 参照があるため、VS Code（リポジトリ上で `.` キーを
押して開く github.dev を含む）では入力補完と検証が効きます。編集したら次を実行してください。

```sh
npm run validate
```

### いずれの場合も

会則の変更には理事会の決議が必要です（第26条）。JSON への反映はプルリクエストで行い、
決議を経てから main へ取り込んでください。

## データ形式

### 条番号は保存しない

条番号は配列順から自動採番されます。章をまたいで通し番号になり、附則は採番の対象外です。

そのため**条を挿入・削除すると、それ以降の条番号がすべてずれます**。会則の本文には
「第6条の義務に違反する行為」（第8条）のように条番号での参照が直接書かれているため、
条を増減させたときは参照の書き換えが必要です。

`npm run validate` は存在しない条への参照を検出しますが、参照先が意味的に正しいかまでは
見ていません。条の増減を伴う改正では、既存の参照を目視で確認してください。

### `id` は変更しない

条と章の `id` は、条番号がずれても壊れない固定の識別子です。公開ページの恒久リンク
（`#art-member-duties` など）に使われます。**一度付けた `id` は変更しないでください。**
見出しを直しても `id` はそのままにします。

編集ページでは `id` を表示していません。変更を誘って既存のリンクを壊すのを避けるためで、
新しい条には `a-3f9c2b1d` のような値が自動で振られます。意味のある英字スラッグに変えたい
場合は、プルリクエスト上で直してください（取り込まれる前なら安全に変えられます）。

### 附則

制定・改正のたびに `supplementaryProvisions` へ 1 件追加します。日付は ISO 形式で保存し、
表示時に和暦へ変換されます。

```json
{
  "kind": "一部改正",
  "effectiveDate": "2026-04-01",
  "resolvedOn": "2026-03-15",
  "resolvedBy": "理事会",
  "reason": "会費の改定"
}
```

`effectiveDate` は議決前の改正案では空にします。**空の施行日が「まだ施行されていない」ことを
表します**。状態を持つ項目は別に置いていません。

`npm run validate` は施行日のない附則を警告として通し、`npm run validate:strict`（main への
公開時に走る）はエラーにします。改正案の段階で CI が落ちないようにしつつ、日付を埋め忘れたまま
公開されるのは防ぐためです。

`resolvedOn`・`resolvedBy`・`reason` のうち `reason` は編集ページから提出すると必ず入ります。
議決日と議決機関は決議のあとに書き入れてください（既存の 6 件は施行日しか記録が残っていません）。

### スキーマを変えるとき

`schema/*.json` を直したら `npm run gen` で生成物を作り直し、まとめてコミットしてください。
CI は生成物が最新でないと失敗します。

型定義（`src/types/law.d.ts`）と検証関数（`src/generated/validate-law.mjs`）はどちらも
`schema/` から生成しています。編集ページはこの検証関数を呼ぶので、`npm run validate` と
同じ規則が画面上でも効きます。

**編集ページの入力欄は自動生成ではありません。** 条文の見た目そのままで編集する形にした都合で、
スキーマに項目を足しても画面は追従しません。気づかず放置されないよう、スキーマの項目一覧と
エディタが扱うと決めた一覧を突き合わせるテストを置いてあります。項目を増やすとこのテストが
落ちるので、`src/components/LawBody.tsx` と `src/lib/edit.ts` に手を入れてください。

## 今後の予定

このリポジトリは、一般会員が改正案を提出できるようにすることを目標に段階的に整備しています。

- **Phase 0（完了）** スキーマの確定と閲覧ページの公開
- **Phase 1（完了）** 編集ページ。本文をそのまま書き換え、差分を見ながら改正案を提出できる
- **Phase 2** GitHub 認証の中継。いまは JSON をコピーして貼り付ける手順が要るが、これを
  自動化してボタン一つでプルリクエストを作れるようにする。あわせて新旧対照表を
  プルリクエスト本文に載せる
- **Phase 3** 議決の記録。対面での議決を事務局が書き入れる導線と、将来的にはこの上での
  オンライン議決。施行日と議決日はそこで埋まる
